## Summary

R6 responsive/mobile-first doctrine added to DESIGN-SYSTEM.md (DGN-376).

This release closes the design-system doctrine set through R6 -- the
cross-surface responsive contract. R5 color identity (v1.19.0) was the
prior dependency; R6 lands on top of that foundation.

The doctrine itself: all web and document-type surfaces treat 375 px
(phone minimum) as the base canvas and expand progressively via min-width
media queries. Breakpoints must switch strategy (navigation pattern, table
form), not merely adjust padding. Key defect calls: (a) hiding primary
navigation destinations behind horizontal scroll is a defect; (b)
applying both horizontal-scroll and word-break to the same table is a
defect.

Reference implementation: console v1, landed live 2026-07-31. Console code
is a separate product repo and is outside this release's VERSION/CHANGELOG
scope -- the doctrine doc references it as the canonical implementation
evidence for R6. Console T-011 (bottom tab bar), T-012 (table conformance),
and T-013 (typography) are the live verification set.

R3 enforcement map updated: rows 6 and 7 added. Row 6 (console 375 px smoke)
is v2/prdt-gated; row 7 (all other web surfaces) is explicitly marked
unenforced debt per the "no silent rule" invariant (R3 clause 3 of the Why
section). The former "R6 lint" label in the enforcement map is renamed
"token-drift lint" for accuracy.

## Feature decisions

### R6 doctrine scope: mobile-primary, not mobile-only

Decision point: should R6 mandate mobile-first only, or treat desktop as
the primary design target?

Landed: mobile-primary (375 px base canvas, progressive enhancement). Basis:
the reference implementation (console v1) was designed and verified at 375 px
first; all enforcement gates use 375 px as the smoke threshold. Desktop
variants expand without degrading the mobile baseline. Owner-confirmed at
design-system grill (DGN-376).

### Table conversion rule: natural-language vs value-only split

Decision point: uniform card-conversion vs split behavior by column type?

Landed: split. Natural-language columns -> cards on narrow canvases; value-only
tables retain tabular form with priority-column reduction + frozen first column +
ID/path ellipsis. Basis: value tables (metrics, token registries, version matrices)
lose readability when converted to card stacks; natural-language tables (task
lists, content rows) lose readability when scrolled horizontally. Owner-confirmed
(DGN-376).

### Enforcement tier: console gates now, all-else tracked-debt

Decision point: mandate smoke tests for all web surfaces simultaneously, or
stage by surface readiness?

Landed: staged. Console 375 px smoke is v2 (prdt ticket-close gate, T-ticket
scope). All other web surfaces are explicitly unenforced debt (R3 row 7) -- not
silently assumed. Basis: R3 invariant requires an explicit enforcement point or
an explicit debt row; no implicit rules. Owner decision reflects current surface
inventory (only the console is an active web surface today).
