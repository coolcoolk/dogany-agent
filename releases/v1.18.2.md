# Release notes -- v1.18.2 (2026-07-31)

Type: PATCH/HOTFIX (mirror probe-floor split; no schema change; no
migration required for consumers of this release).

## Summary

Follow-up hotfix on v1.18.1. One commit since the prior release tag.

v1.18.1 replaced the hard version whitelist with a MIN_USER_VERSION=11 floor
plus a capability probe. Live landing revealed a tuning gap: Warg's health-domain
schema sits at user_version=10 (framework migrations 001-010 + health-pack W01-W03;
011_income_kind was never taken, so core version stays 10). The MIN=11 floor
pre-empted the capability probe for this valid v10 lineage -- every required
capability was present, but the floor check rejected it before probe could run.
This violated the "trust the probe" design intent of DGN-654.

v1.18.2 separates the two constants. PROBE_FLOOR_USER_VERSION=10 is the
acceptance floor for the capability probe gate (v>=10 AND probe-pass -> accept;
v<=9 or probe-fail -> reject). MIN_USER_VERSION=11 is retained as the
canonical baseline and the monotonic marker parsed by update.sh reverse-drift
guard -- lowering it would cause instances already on v1.18.1 (MIN=11) to read
the new release as "behind" them, blocking forward propagation.

Release approved by owner: explicit dispatcher authorization (2026-07-31,
DGN-654 worklog entry "릴리스 (2026-07-31) -- shipped: v1.18.2").

## Fixed

### DGN-654: mirror probe-floor split -- PROBE_FLOOR_USER_VERSION=10

`mirror/sdk_bridge.py`:

- Introduces PROBE_FLOOR_USER_VERSION=10 as a separate constant from
  MIN_USER_VERSION=11. The get_conn acceptance gate evaluates:
  user_version >= PROBE_FLOOR_USER_VERSION AND all capability checks pass.
  Schemas at v9 or below are still rejected; a probe failure still fails loudly.
- MIN_USER_VERSION=11 is unchanged: it remains the canonical baseline and the
  scalar the update.sh reverse-drift guard parses. Lowering MIN would cause
  v1.18.1 live instances (already at MIN=11) to treat this fix as older than
  themselves and refuse the update -- the constant must not decrease.
- Restores calendar mirror polling for Warg (health-domain, user_version=10,
  all capabilities present) without requiring a domain schema migration.

`tests/mirror/test_dgn654_version_tolerance.py`:

- Adds test coverage for the probe-floor split: v10 accepted on probe-pass,
  v9 rejected regardless, probe-fail at v10 rejected. Corrects a pre-existing
  baseline assertion that had not been updated after v1.18.1 added roller_log
  to the required capabilities table set (red fixture, now fixed).

Mirror test suite: 335 checks across 9 test files, all green (commit 84bf2f4).
