## 목적 (purpose)

앵커: 알림·재시작 통지 HTML 태그 깨짐 회귀 복구 + 락스텝 재발 방지 (DGN-906/907).

v1.36.0 업데이트가 vendored bridge/formatting.py에 push 통로용 정리 함수
(`sanitize_message_for_telegram`)를 누락시키면서, 모든 shell-rail push(재시작 통지·
리마인더·cron·proactive-push)가 평문 폴백으로 떨어져 HTML 태그가 날 것으로 노출됐다.
근본 원인은 오래된 `.dogany-preserve` 핀이 formatting.py를 얼려 canonical 픽스가
착지하지 못한 것(락스텝 파손). 이번 릴리스는 회귀를 복구하고, 같은 유형을 실행지점에
게이트로 봉쇄한다.

Riders:
- DGN-891 tag-balance back-land: 전송 분할 경계 HTML 태그 밸런싱 + 태그제거 폴백을
  canonical template에 정합(라이브 -> canonical superset). streaming.py 가드 복구 포함.
- DGN-905 vendored bridge 핀 정합: OSS main 87ac8ca로 핀 bump -- 드리프트 0.

- 왜: (1) 락된 픽스가 업데이트마다 "왔다갔다"하던 체감의 실체는 preserve 핀 하나에 뭉친
  양방향 드리프트였다 -- formatting.py는 핀에 얼어 canonical 픽스가 못 오고(DGN-906),
  streaming.py는 핀이 없어 라이브 픽스가 덮였다(DGN-891 회귀). canonical == 라이브로
  수렴시키고, 핀 만료/계약을 실행지점 게이트로 강제해 뿌리를 제거한다.
  (2) push 통로가 전제하는 계약이 vendored bridge에서 성립하는지 아무도 검증하지 않아
  회귀가 조용히 통과했다 -- 업데이트 완료 시점 계약 스모크로 봉합.

## Highlights

1. 재시작·알림 통지의 날 HTML 태그 노출이 복구된다. push 통로가 부르는 정리 함수가
   vendored bridge에서 누락됐던 회귀를 복구 -- 모든 shell-rail push가 정상 렌더된다.
   (DGN-906)

2. 텔레그램 HTML 태그가 전송 분할 경계에서 깨지던 문제가 수정된다. 열린 태그 LIFO
   자동 닫기, 경계 넘는 span 재개, 태그제거 폴백. v1.36.0에서 핀 부재로 덮였던
   streaming.py 밸런싱 가드도 복구된다. (DGN-891)

3. 락스텝 재발 방지 게이트가 추가된다. (a) 업데이트 완료 시 알림 전송 계약을 자동
   점검하고 실패 시 업데이트를 실패 처리(버전 스탬프 없음) + 경고 통지. (b) 만료된
   보존 핀(target-version 소비됨)을 자동 무효화하되, 재착지 직전 계약 스모크 통과 시에만
   착지 -- 실패 시 핀 유지 + 하드 경고(back-land 필요 신호). (DGN-907)

4. vendored bridge 핀이 OSS main(87ac8ca)으로 정합된다. release 게이트 5c 드리프트 0.
   콘텐츠는 DGN-891 back-land로 이미 착지 -- 핀은 provenance 정합만. (DGN-905)

## Changes by Ticket

### DGN-906 -- push-rail sanitizer 소실 회귀 복구 (anchor)

**증상:** 재시작 완료 통지 및 모든 shell-rail push에서 `<blockquote expandable>` 등
HTML 태그가 렌더되지 않고 글자 그대로 노출. markdown 변환도 안 됨.
**근본 원인:** routines/push.sh가 `from bridge.formatting import
sanitize_message_for_telegram`를 호출하는데, vendored bridge/formatting.py에 이 함수가
없어 ImportError -> 평문 폴백. 함수는 canonical(v1.31.0/DGN-822)에 있었으나
`.dogany-preserve` 핀이 formatting.py를 얼려 착지 차단.
**복구:** DGN-891 back-land로 canonical formatting.py가 라이브 superset이 되어 핀 제거
안전 조건 충족 -> update --bridge-accept 경로로 착지 예정. 계약 스모크로 검증.

### DGN-891 -- tag-balance back-land (rider)

라이브 Metal의 태그 밸런싱 가드(전송 직전 열린 태그 자동 닫기·재개) + 태그제거 폴백을
canonical template에 정합. formatting.py/bot.py/streaming.py + test_dgn891_tag_balance.py
(27 그린). canonical이 라이브 superset임을 byte-parity로 확인 -- 미흡수 라인 0.
v1.36.0에서 핀 부재로 덮인 라이브 streaming.py 가드는 이 착지로 복구된다.

### DGN-907 -- preserve-pin lockstep gate (rider)

update.sh에 두 게이트 배선:
- post-flight 계약 스모크: 라이브 인스턴스가 push.sh sanitize 계약을 만족하는지 검증,
  실패 시 exit 4(버전 스탬프 전) + 경고 통지.
- 하이브리드 핀 만료: `# prune-after: vX.Y.Z` 주석 파싱, 만료 + 수신 payload 계약 통과 시
  핀 자동 무효화(재착지 경로 개방); payload 실패 시 핀 유지 + 하드 경고.
selftest 24/24. 라이브에서 게이트 실측 발화 확인.

### DGN-905 -- vendored bridge 핀 정합 (rider)

agents/.template/bridge/UPSTREAM.md 핀을 e0cb5c3 -> 87ac8ca(OSS main). 콘텐츠는 DGN-891
back-land + 기존 template countdown으로 이미 존재 -- 파일 재복사 없이 provenance 핀만
정합(재복사 시 canonical-only 기능 대량 손실 위험). release 게이트 5c 드리프트 0.

## Feature Decisions

- **핀 만료 강제 강도 (DGN-907, 형님 확정 2026-08-16):** 경고형 대신 절충형 채택 --
  만료 핀 자동 무효화 + 재착지 직전 계약 스모크 통과 게이트. 방치 재발 차단(하드 강제)과
  Metal-ahead 회귀 방지(계약 게이트)를 동시 확보.

- **DGN-905 재복사 금지:** vendored bridge는 canonical-only 델타(DGN-759/902/822 등)가
  OSS 위에 쌓인 superset -- OSS 트리 재복사는 이 델타를 덮으므로 금지. 핀은 provenance
  정합만(DGN-593: 실제 착지 게이트는 per-file manifest 3-way).
