## Purpose

Self-update 버전 스큐 하드닝 + 업데이트 알림 단일 fold.

v1.27.0에서 스컬 인스턴스가 업데이트 후 크래시 루프에 빠진 실제 사고의 근본 원인을 제거한다:
bot.py가 새 버전으로 착지하는 동안 messages.py가 "로컬 편집" 오분류로 동결되어
`messages.CMD_DESC_KILL` 미정의 런타임 오류가 발생. 두 가지 인터록 가드로 봉쇄한다.
업데이트 알림 단일화(DGN-718)는 인접 UX 표면 수정으로 같은 릴리스에 묶는다.

## Changes

### DGN-762 -- self-update 버전 스큐 충돌 근본 수정 + selfcheck 상수 해석 게이트

**R1: update.sh 조상 증명 범위 확장 (commit 5524224)**

DGN-757에서 구현한 `bridge_vendor_ancestor()` git-blob 조상 증명을 브릿지 class 2/5에서
class **3(로컬 편집->보존됨)** 및 **4(충돌->유지됨)** 로 확장한다.

인스턴스 브릿지 파일의 바이트가 템플릿 벤더 이력의 어느 시점과 byte-exactly 일치하면
"순정 구버전 벤더 시드"임이 증명됨 -> 백업 후 현행 템플릿 버전 착지. 조상 증명 실패(진짜
수동 편집) 또는 git 미도달 -> 기존 보존/유지 동작. 착지 후 end-state는 항상 incoming
channel 템플릿과 일치해 스큐가 없다.

실제 사고 경위: bot.py가 DGN-677 class-5 경로로 새 버전으로 착지하는 동안, messages.py는
DGN-757 이후에도 class-3/4 경로에서 조상 증명 없이 "보존" 판정을 받아 stale 버전에 동결됨.
결과: `messages.CMD_DESC_KILL` 런타임 미정의 -> 크래시 루프.

class-4 "절대 자동 착지 금지" 보호 규칙의 적용 범위: byte-identity가 vendor 이력에 있으면
사용자 저작물이 없음을 증명 -> class-4 레이블 자체가 오분류였으므로 override 정당.

**R2: agents/.template/bridge/__main__.py selfcheck 상수 해석 (commit 5524224)**

pre-restart `_selfcheck`(self_restart.sh가 기존 브릿지를 종료하기 전 소비)에 크로스 모듈
상수 해석 AST 검사를 추가한다. bridge/*.py에서 `messages.<NAME>` ref와
`from bridge.messages import <NAME>`을 스캔하고 실제 messages 모듈에 대해 getattr로
해석 시도. 미정의 상수가 있으면 selfcheck FAIL -> 재시작 차단(기존 브릿지 생존).
결과: bot.py<>messages.py 스큐는 크래시 루프 대신 재시작 거부로 처리된다.

검증 근거:
- Adversarial real-code grill: LAND-READY. R2 픽스처가 스컬 스큐 정확히 재현(rc=1), 일관성 있는 트리에서 PASS(93 ref, 0 miss). R1 모든 index-build-failure 경로가 preserve/hold로 안전 강등, 맹목 착지 없음.
- Doctrine-reviewer: PASS-WITH-CONDITIONS. 조건 = `--all` 조상 스코프 근거 기록. 이행: 착지 대상은 항상 incoming channel 템플릿 -> end-state 템플릿 일치 = 스큐 없음. class-4 override는 byte-identity가 사용자 저작을 반증하므로 정당.

락 독트린:
- (a) update 실행의 계약은 incoming 템플릿으로의 수렴. 조상 증명은 오직 "로컬 바이트가 사용자 저작 정보를 담는가"를 게이트할 뿐, 버전 순서를 판정하지 않는다.
- (b) class-4 "절대 자동 착지 금지"는 사용자 저작 divergence를 보호. byte-identity to vendor history는 저작물 없음을 반증 -> class-4 레이블 오분류였음.

### DGN-718 -- 업데이트 가능 알림 = 단일 펼침 인용 블록 (commit 94af1be)

`routines/version-check.py` `_build_user_notice`가 헤더/펼침-노트/꼬리 세 개의 별도
`<blockquote>` 덩어리를 방출하던 문제 수정. 오너가 세 개로 쪼개진 말풍선을 보는 회귀였다:
단일 fold 통합(오너 지시, 2026-08-04)이 branch-only로 릴리스되지 않은 채, DGN-738/742
후속 작업이 3-block 구조 위에 재건하면서 삭제됨.

재적용: 알림 전체가 **단일** `<blockquote expandable>` -- 축소 미리보기 3줄(헤더 / "지금
업데이트하실래요?" / "▸ 업데이트 노트"), 릴리스 노트 요약 fold 아래. 노트 없는 경우
plain 2줄 blockquote로 강등.

`agents/.template/routines/tests/test-dgn718-single-fold-notice.py` (16 assertions, 모두
pass)를 누락된 어셈블리 가드로 추가 -- 이 회귀가 조용히 재발하는 것을 막는다.
