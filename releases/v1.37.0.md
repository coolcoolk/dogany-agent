## 목적 (purpose)

앵커: 출력 규율 + 브릿지 인터랙션 품질.

브릿지 인-플라이트 기본 동작을 "즉시 끊기"에서 "5초 기다렸다가 끊기"로 역전하고,
/queue(명시적 대기열)와 /stop(버퍼 버리기) 의미론을 확정했다. 출력 게이트에 BACKREF·
answer-omission 카나리를 배포(검출 전용 Phase-1)하고, 카운트다운 종료 시 탭 가능한
완료 어포던스를 추가하며, 슬래시 명령어 메뉴를 단일 소스에서 관리하고, /btw 응답을
공용 HTML 포매터로 라우팅했다. 통합 수정 4건 동반.

Anchor: DGN-911
Riders: DGN-913, DGN-914, DGN-915, DGN-919, DGN-920, DGN-922

## Highlights

1. 인-플라이트 기본값 역전 -- 메시지가 와도 5초 기다린다. 즉시 끊던 기본 동작을
   5초 디바운스 후 끊기로 전환. /queue는 끊지 않고 명시적 대기열에 추가; /stop은
   버퍼를 버리고 취소. (DGN-911)

2. 카운트다운 종료 탭 어포던스. 타이머가 끝나면 바로 탭할 수 있는 완료 버튼이 뜬다
   -- 타이머 종료 후 무반응 구간(dead-air) 제거. (DGN-915)

3. 슬래시 명령어 메뉴 단일 소스. COMMAND_MENU_SPEC이 /-팝업 메뉴와 /help 둘 다를
   주도 -- 순서·문구가 항상 일치. 오너 확정 문구 고정. (DGN-919)

4. /btw 응답 HTML 포매터 적용. /btw 포크 출력이 공용 HTML 포매터를 거쳐 **bold**가
   제대로 렌더된다(날 `**` 노출 제거). (DGN-920)

5. 출력 게이트 카나리 2종 배포(검출 전용). BACKREF 검출기(최종 답이 접힌 로그를
   참조하는 케이스 플래그)와 answer-omission 스윕 데이터 기반 구축. (DGN-913, DGN-914)

6. 통합 수정 4건. /stop 후 유령 턴 제거; 카운트다운 완료 버튼의 20분 만료 게이트 통과;
   긴 /btw 응답 분할+전달; /btw 포크가 메인 대화를 굶기지 않음. (DGN-922)

## Changes by Ticket

### DGN-911 -- bridge in-flight default inverted: 5 s debounce + /queue (anchor)

**변경 전:** 실행 중에 메시지가 도착하면 즉시 인터럽트 (interrupt-default).
**변경 후:** 5초 대기(디바운스) 후 끊기 (debounce-interrupt). 사용자가 짧은 후속
메시지를 보내도 실행 중인 턴이 즉시 취소되지 않는다.

신규 `/queue` 슬래시 커맨드: 인터럽트 없이 메시지를 명시적 대기열에 추가. 실행이
끝나면 대기열 메시지가 순서대로 처리된다.
`/stop` 의미론 확정: 버퍼된 메시지를 버리고 취소 (기존 하드 인터럽트 동작 보존).

메뉴 문구(오너 확정): `/queue` 복사 = '메시지 큐에 넣기' / 'Add to queue'.

### DGN-913 -- output-gate BACKREF detector (canary, detect-only)

최종 답변이 접힌 진행 로그(fold)를 실질적 내용 전달 수단으로 역참조하는 케이스를
검출하는 카나리 레이어. 이번 릴리스는 detect-only -- 플래그만 기록하고 차단은
Phase-2에서.

### DGN-914 -- output-gate answer-omission sweep: Phase-1 data foundation

멀티-질문 프리필터 + 히트-턴 로우 카나리 로깅 + Phase-2 수확을 위한 answer-omission
스윕 기반 구축. 이번 릴리스는 데이터 수집 전용(검출·차단 없음); 쌓인 데이터로
Phase-2 집행 기준을 도출한다.

### DGN-915 -- countdown timer END completion affordance

자연 종료 시(`<id>.done` 마커 존재) 카운트다운 메시지에 탭 가능한 완료 버튼이 표시된다.
타이머 종료 후 아무것도 뜨지 않던 dead-air 구간 제거. 취소(마커 없음)는 기존대로 버튼 없음.

### DGN-919 -- slash command menu single-sourced (COMMAND_MENU_SPEC)

`COMMAND_MENU_SPEC` 단일 정의가 BotCommand 등록(/-팝업)과 /help 출력 둘 다를 주도한다.
이전: 두 곳을 별도로 유지 -> 순서·문구 드리프트 가능.
이후: 소스 하나에서 둘 다 파생 -> 항상 일치.
오너 확정 문구 고정; 변경 시 오너 게이트 필요.

### DGN-920 -- /btw fork output via shared HTML formatter

`/btw` 포크 응답이 공용 `formatting.py` HTML 포매터를 경유하도록 배선 변경.
**bold** 렌더, 마크다운 sanitize, Telegram HTML 안전 출력이 메인 대화와 동일하게 적용된다.
이전: /btw 포크가 포매터를 건너뛰어 `**bold**` 날 마커가 노출.

### DGN-922 -- release-gate integration fixes (4 items)

릴리스 게이트에서 발견된 통합 버그 4건 수정:

1. **/stop 후 유령 턴**: /stop이 실행 중인 턴을 취소한 뒤 빈 응답("") 턴이 사용자에게
   노출되던 문제 제거.
2. **countdown done-button 20분 만료 게이트**: 카운트다운 완료 버튼이 Telegram의 20분
   콜백 만료 게이트에서 stale 처리되던 문제 수정 -- 완료 어포던스가 정상 동작.
3. **긴 /btw 응답 분할 전달**: /btw 응답이 Telegram 메시지 크기 상한을 초과할 때
   분할 없이 실패하던 경로를 분할+전달로 수정.
4. **/btw 포크 메인 대화 굶기기**: /btw 포크 처리가 메인 대화 턴 스케줄러를 블로킹하던
   경쟁 조건 제거.

## Feature Decisions

- **인터럽트 디바운스 기간 (DGN-911, 형님 확정 2026-08-17):** 5초 채택. 즉시 끊기(0s)와
  전혀 안 끊기(∞) 사이 균형점 -- 짧은 후속 메시지 보정이 가능하면서 응답성 유지.

- **/stop 버퍼 버리기 (DGN-911, 형님 확정 2026-08-17):** /stop은 대기열 버퍼를 버린다.
  사용자가 명시적으로 멈추는 의도가 있으므로 "대기하던 것도 함께 폐기"가 올바른 의미론.

- **출력 게이트 카나리 Phase-1 = detect-only (DGN-913/914):** 집행(차단)은 데이터
  기반 기준 확정 후 Phase-2에서. 조기 차단이 정상 패턴을 막는 false-positive 위험
  > 한 릴리스 검출 전용 유예.

## Deferred

- DGN-913/914 Phase-2: 카나리 데이터 수집 후 집행 기준 도출 + 차단 배선.
- DGN-904 공개 일원화 forcing point 배선 + 릴리스노트 유저언어 번역 게이트
  (설계 미완, design grill 미실행) -- v1.38.x 앵커 후보.
