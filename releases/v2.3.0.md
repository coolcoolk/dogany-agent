## Highlights

### 1. 한 줄 설치 (DGN-1288)

받는 곳과 설치되는 곳이 달랐다. 사용자는 저장소를 클론하고, 어디에 받을지 정하고,
그 안에서 `install.sh` 를 찾아 실행해야 했다. 그런데 실제 설치 위치는
`~/.dogany/framework` 로 따로 있었다. **"방금 받은 이 폴더는 뭐지"가 남았다.**

이 판에서 진입점 `get.sh` 가 그 층을 없앤다. 한 줄을 붙여넣으면 git 준비 ->
프레임워크 내려받기 -> 설치 마법사로 이어지고, **받는 위치를 묻거나 고르게 하는
단계가 없다.** 받는 곳이 곧 설치되는 곳으로 고정돼 있다.

안전장치 셋이 실측으로 확인됐다:

    중단 내성    다운로드가 끊겨도 반쪽짜리가 설치 자리에 남지 않는다
                 (임시 위치에 받고 완료 후 이동)
    재실행 안전  같은 명령을 다시 붙여도 안전하다. 이미 받아둔 것을 쓴다
    오프라인     네트워크가 끊겨 있으면 받아둔 판으로 그냥 진행한다

파이프로 흘려받다 잘려도 아무것도 실행되지 않는 형태로 짜여 있다(함수 정의만
먼저 오고 호출은 마지막 한 줄).

### 2. 막다른 길에서 다음 행동이 화면에 남는다 (DGN-1288 phase 2)

의존성 자동 설치가 Debian/Ubuntu 에서만 됐다. 다른 배포판은 "직접 설치한 뒤 다시
오세요"로 끝났다. 이 판에서 Fedora / RHEL / Arch / openSUSE / Alpine 까지 넓혔다.

그래도 모르는 환경이면 **막다른 길이긴 하되 가장 짧은 막다른 길**이 되게 했다:
필요한 패키지 이름, 그 환경에 맞는 설치 명령, 그리고 설치 후 다시 실행할 명령이
전부 화면에 찍힌다. 사용자 기억에 기대는 문장("같은 명령을 다시")을 없앴다.

### 3. 떼어낸 작업의 완료가 다시 도달한다 (DGN-1347)

복귀 경로가 import 한 줄 누락으로 **작업이 끝난 직후 크래시**하고 있었다. 작업은
성공으로 끝나므로 실패가 어디에도 안 보였고, 완료 통지만 조용히 사라졌다.

같은 날 이 결함이 만든 2차 피해도 같이 정리했다: 완료 통지가 안 오니 종결 백스톱이
멀쩡히 끝난 작업 9건을 "만료"로 잡아 올렸다.

### 4. 스킬 스텝의 레인 선언 표면 (DGN-928)

프로즈로 적힌 절차에는 실행 순서 강제가 없다 -- 모델은 서술 순서가 아니라 연상
적합도로 실행한다. 이 판은 그 문제의 **선언층**을 놓는다.

`product.yaml` 에 additive `lanes:` 블록으로 스텝별 rule/llm 레인, `kind`
(value|gate|verify), carrier 를 선언하고 발행 게이트가 검사한다: carrier 실존,
kind 어휘, `after:` 참조 해소 = 차단. 프로즈 스멜(수식이 산문에 있음, 룰 출력을
되무르는 부정 가드) = 경고.

**레인 배정의 옳고 그름은 기계가 판정하지 않는다.** 그리고 `after:` 는 아직 선언일
뿐 실행 순서를 강제하지 않는다 -- 그 집행 기계(DGN-943)는 미착수다. 코드 주석,
린트 출력, 독트린 문안 세 곳에 같은 문장으로 명시했다.

### 5. 조용한 실패 둘 (DGN-828 / DGN-1350)

**이름표**: 재시작·업데이트 알림의 에이전트 이름을 읽는 시점에 해석한다. 설정에
없으면 페르소나 파일에서 읽고, 그것도 없으면 접두어 없이 보낸다. 자리표시자
문자열이 사용자 화면에 닿는 경로가 사라졌다.

**한도 감지**: 모델 한도 소진을 잡는 두 경로가 서로 다른 문구를 보고 있었다. 한도
안내 문구가 바뀌자 한쪽만 못 알아들어, 다음 작업을 자동으로 다른 등급으로 돌리는
장치가 안 돌았다. 두 경로가 같은 문구 집합을 받는지 테스트가 검사한다.

## 알려진 잔여

   아무것도 보장하지 않는다.
2. **`lanes:` 를 선언한 유닛이 0개다.** 스키마·린트·게이트는 살아 있고 선언이
   없으면 통과한다(units 18 / lanes-declared 0). 첫 실사용은 라이프킷 식단 스킬
   예정 -- 그쪽 레인.

   진입부 문구뿐이다. 마법사 본체는 한 줄도 읽지 않았다. 형님 지시로 devkit
   착지 이후로 파킹됐다.
4. **발주 중 사망 시 미커밋 작업 유실** (DGN-1351). 2026-09-08 22:03 에 14분치
   실작업이 실제로 증발했다. 이 판에 수정 없음.
5. **선언-실물 감사의 거짓 양성** (DGN-1354, P1). 배달층과 활성층을 구분 못 해
   스킬을 꺼둔 인스턴스가 매주 거짓 경보를 낸다. 설계 확정, 구현 미착수.
6. **팩 핀이 재구성 불가능한 지점을 가리킴** (DGN-1353). 태그 없는 버전에 핀이
   박히는 걸 막는 게 없다. 원인 규명 전.
7. **라이프킷 안정성 관측창 리셋됨** (2026-09-09, 형님 판정). 술어 (iv) 위반.
   프레임워크 핀 해제(P3)가 그만큼 밀린다. 이 판과 독립된 축이다.
8. **위임 감사 측정 불능** (DGN-1007, P1). 트레일러 커버리지 7%. 이 판의 커밋
