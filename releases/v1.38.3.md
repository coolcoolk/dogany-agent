## 목적 (purpose)

앵커: 알림 무음 정책(notify_policy) -- 진행 소음은 무음, 신호는 울림. 브릿지가
내보내는 각 발송에 알림 "클래스"를 부여하고, 클래스별로 텔레그램 알림을 무음/
소리로 라우팅하는 2메커니즘을 도입한다.

문제: 브릿지의 여러 발송(중간 진행 fold, 대시보드 재생성 핀, 옵션 버튼 부록,
답변 draft, 카운트다운)이 알림 정책 없이 각자 하드코딩된 무음/소리로 나갔다.
진행 소음이 울리거나, 반대로 신호가 묻히는 비일관이 있었다. v1.38.3은 클래스 ->
무음 결정을 단일 resolver(notify_silent)로 통합하고, 클래스별 config override를
연다.

Anchor: DGN-932

## Highlights

1. 클래스별 알림 정책 (DGN-932). 발송마다 클래스 부여, `notify_silent(class)`가
   무음 여부(disable_notification)를 결정: config override > 락된 기본값 >
   미상 클래스=소리(one-shot 발송은 명시 태그 없으면 텔레그램 기본 소리 유지).

2. 메커니즘 A -- 편집 표면 말풍선. 알림은 **첫 발송에서 한 번** 결정되고 이후
   in-place 편집은 텔레그램 레벨에서 알림 없음. 클래스: `draft`(답변 도착=신호,
   소리) / `fold`(중간 진행 서술=소음, 무음) / `countdown`(첫 tick=세트 시작
   신호, 소리 -- DGN-594 항상무음 발송을 대체) / `dashboard`(루틴 보드 재생성,
   무음; 핀도 같은 값 추종).

3. 메커니즘 B -- one-shot 메시지. 텔레그램 기본 소리; 발송처가 클래스 태그로
   무음을 opt-in. 현재 `options_prompt`([[OPTIONS]] 버튼 부록)만 무음 태그 --
   소리 나는 본문 답변을 버튼 메시지가 덮지 않도록. system/error/timeout/file/
   command 응답은 무태그=소리 유지.

4. 락된 무설정 기본값 (owner lock 2026-08-19):
   draft=loud, fold=silent, countdown=loud, dashboard=silent,
   options_prompt=silent.

5. config override. `NOTIFY_POLICY` env = "class=silent" / "class=loud" 공백/
   콤마 리스트(예: `NOTIFY_POLICY="fold=loud countdown=silent"`). 오설정 항목은
   스킵(부팅 크래시 없이 기본값 폴백), 미상 클래스명은 보존(전방호환 inert).

미설정/빈 값이면 락된 기본값 적용 -- 일반 인스턴스 무영향(opt-in). first-tick
loud(M1)와 dashboard 핀 주석(m2)은 final grill 조건부 GO 반영분.
