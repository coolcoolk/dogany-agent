## Purpose

Close the silent bridge-drift gap. When a bridge file is edited on a live
instance or advanced in the canonical template, that divergence could freeze a
file at CONFLICT-preserve and silently stop future canonical fixes from landing
on it. This release adds write-side and reconcile-side forcing points that make
the drift conscious and visible, and moves the update-completion notice off the
English CHANGELOG scrape onto a user-language summary field.

## Changes

### DGN-625 -- pre-commit bridge pin-bump guard
A canonical change under the vendored `bridge/` tree must bump the pin
(`UPSTREAM.md`) in the SAME commit, or the pin silently goes stale: the
canonical is fixed but the pin is not bumped, so the drift is invisible until a
release surfaces it. The pre-commit hook now blocks a bridge change that does
not stage a pin bump alongside it (pure pin-only commits pass). This is the
write-side forcing point paired with the release.sh pin gate.

### DGN-724 -- instance bridge/ edit forcing point + STALE-PRESERVE surfacing
Two paired guards. (1) A live instance lays `bridge/` at its root (not under
`agents/.template/`); hand-editing it there silently diverges the file from the
canonical template, so the next update classifies it as CONFLICT and preserves
it frozen -- future canonical bridge fixes then stop landing with no signal. The
pre-commit hook now forces a conscious acknowledgment (`--no-verify`) before
that drift is committed; it is a forcing point, not an absolute wall, and stays
inert for canonical-layout and merge/rebase/cherry-pick landings. (2) In the
reconcile class-4 preserve path, `update.sh` now compares the incoming template
sha against what was last landed and, when the canonical side ALSO advanced,
emits a `STALE-PRESERVE` report line plus a WARN -- so an instance silently
missing canonical fixes on a frozen file is now always visible. Existing
`CONFLICT` report lines and counts are untouched.

### DGN-699 Spec A -- user-facing update summary field
The update-completion notice fold scraped the English CHANGELOG version section.
CHANGELOG is estate English-rule (model-facing), so the owner saw English text
and internal jargon in a user-facing notice. A release note now carries a
machine-readable `user-summary` block (ko/en) near the top; `self-update.sh`
extracts the summary for the resolved language (`DOGANY_LANG` ->  `AGENT_LANG`
-> en) and uses it as the notice body, falling back to the English CHANGELOG
scrape only for releases that predate the block. CHANGELOG stays English and
untouched. The composed notice is handed to the restart worker, so the
restart-complete push renders the same user-language summary.

### DGN-702 -- drop self-check ad-suffix from the restart notice
The restart-complete notice no longer advertises the background self-check
(the "... 이어서 자가점검 돌립니다 ..." suffix). The self-check runs as a silent
background turn (NO_PUSH when healthy), so advertising it made the owner wait
for something that never surfaced. A normal restart with nothing to resume now
sends the clean "재시작 완료" line only; the resume path (auto pick-up + the ↪
resume notice + report) is unchanged, and failures still warn.

## Notes

- DGN-702 required no canonical code change: the canonical restart notice
  already defaulted to the clean "재시작 완료" line and never carried the
  self-check ad-suffix (the suffix existed only transiently on the live Metal
  shadow, already removed there). The policy is therefore already satisfied in
  the template; this entry records the theme, not a diff.
- DGN-699 Spec A ships the summary-field mechanism only. The fold streaming
  convergence (spec-v2 growing fold, canonical back-landing) is deferred to a
  separate v1.27.0 bridge-convergence release.
