## 목적 (purpose)

이번 마이너 = lifekit 독립 제품 라인 분리(적출). lifekit이 프레임워크 코어 트리 안에
살던 것을 밖으로 빼내, 프레임워크는 "호환 계약 위에 팩을 얹는" 코어만 남기고 lifekit은
독립 팩(dogany-lifekit)으로 자립한다. 유저 체감 변화 0 -- 설치 레이아웃/런타임 경로 불변,
라이브 인스턴스 무접촉.

- 왜: lifekit 소유가 이미 Skull end-to-end인데(DGN-789) lifekit이 프레임워크 레포 안에
  있어 매 콘텐츠 착지가 프레임워크 쓰기 = Metal 승인세를 유발. 적출 = 승인세의 root
  제거(팩을 Skull이 직접 저작·배포). (DGN-681, DGN-803, 오너 디렉티브 2026-08-09)

### Added
- 팩 계약 검증기 compat-lint (scripts/pack/compat-lint.sh): 팩 매니페스트+payload가
  프레임워크 계약을 만족하는지 publish/install 양단에서 검증(6+위생 체크). legacy 팩
  (contract_version 없는 기존 dev/health-trainer)은 무영향(legacy-grace).
- pack_install kit-class 설치: kit 팩을 카테고리별로 인스턴스에 배치 + reverse-drift 가드
  (인스턴스가 팩보다 최신이면 코어 덮어쓰기 SKIP = 라이브 안전) + i18n JSON 병합.

### Changed
- lifekit(database/lifekit.py, schema, 마이그레이션, service/lifekit, 도메인 스킬 8종,
  번들 루틴/config)을 프레임워크 코어에서 적출 -> 독립 팩 dogany-lifekit로 이동.
- mint: lifekit DB 초기화를 무조건 경로에서 kit 활성화(팩 설치) 시점으로 이동. 비-lifekit
  민팅은 lifekit 없이 정상 완료.
- cadence-gate의 lifekit pin 강제는 compat-lint 3점 버전 검사로 이설.

### Notes
- lifekit 팩 자체(payload + pack/lifekit/v1.0.0 발행)는 후속 단계(Skull, 팩 레포 sole-writer).
- 라이브 리스크 0(조건부): 라이브 pin > 프레임워크 pin이라 reverse-drift 가드가 이미
  덮어쓰기를 막고, 소스 제거가 인스턴스 삭제로 전이되지 않음.
