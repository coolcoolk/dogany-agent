## 목적 (purpose)

앵커: usage-gate 과차단 완화 (DGN-835).
max_20x 플랜 리셋 임박(24h 내) 잔여예산 재계산(CAP 97) + MUST-USE 편집기 heavy-gate 예외 +
창별 차단 복구 자동화(5h 큐 재개 / 7d /usageretry + 리셋 후 fresh 버튼) +
정본 stale 경보(2일 연속 defer) + 병렬 herd 봉쇄(ledger 시간버킷 원자화) +
5h resets_at 캐시 추가(기존 오스케줄 버그 동시 수리).

Riders:
- 인지 출력 포맷 (DGN-829): telegram.md bold 규칙 정정 + 이모지 섹션헤더 채택 +
  SECTION_GLYPHS 팔레트(복잡·긴 내용에서만 게이트, 단순답=평문) +
  AGENT.md L0 응답골격 게이트 명문화 + config SECTION_GLYPHS env +
  self-update 통지 라벨 글리프화.
- 통지 테스트 평문화 위생 (DGN-840, dec-117 정합).

- 왜: (1) usage-gate가 max_20x 플랜에서 리셋 임박 시에도 예산을 재계산하지 않아
  실제 남은 예산 대비 과차단이 발생하고 있었다. baseline-editor 등 필수 편집기마저
  heavy-gate에 잡혀 에이전트 운용이 끊기는 사례 반복 확인. 창별 복구 경로도
  수동이었다 -- 이 릴리스에서 재계산 + 예외 + 자동복구를 일괄 수리한다.
  (2) 텔레그램 브릿지가 이미 <b>를 렌더하는데 AGENT.md가 마크다운 bold를 추가
  지시하여 이중 적용 오류가 발생했다. 이모지 섹션헤더 팔레트(SECTION_GLYPHS)가
  없어 복잡한 응답 포맷이 미정의 상태였다 -- telegram.md 정정 + 팔레트 도입.
  (3) dec-117 정합 통지 테스트 케이스가 평문 기준으로 정렬되지 않아 위생 처리.

## Changes by Ticket

### DGN-835 -- usage-gate 과차단 완화

**리셋 임박 잔여예산 재계산 (max_20x 한정)**
24h 이내 리셋 임박 시 남은 예산을 재계산하여 CAP 97 클리핑 적용.
기존: 리셋 임박 무관하게 고정 CAP 비교 -> 과차단 발생.
수정: `resets_in_hours < 24` 조건에서 remaining_budget 기반 재계산 후 CAP 97 이하 클리핑.

**MUST-USE 편집기 heavy-gate 예외**
baseline-editor, 문서편집기 등 Sonnet/Haiku 모델 기반 필수 편집기를 MUST_USE_EDITORS
레지스트리에 등록. heavy-gate PreToolUse 훅에서 레지스트리 조회 후 예외 통과.
기존: 편집기 모델 불문 heavy dispatch 판정 -> 에이전트 운용 단절.
수정: MUST_USE_EDITORS 예외 우선 처리.

**창별 차단 복구 자동화**
- 5h 창: 차단 -> 잔여 heavy 요청을 큐에 보존, 5h 리셋 시 자동재개.
- 7d 창: 차단 -> 유저 알림 발송 + /usageretry 슬래시 커맨드 등록 +
  7d 리셋 완료 후 fresh 버튼 재알림.
기존: 수동 확인 + 재실행.

**정본 stale 경보**
2일 연속 defer 카운터 초과 시 정본 stale 경보. 감지 즉시 노티 발송.

**병렬 herd 봉쇄 (ledger 시간버킷 원자화)**
ledger 버킷 write를 원자 트랜잭션으로 보호. 동시 heavy 요청 스파이크에 의한
버킷 경쟁 조건 제거.

**5h resets_at 캐시 + 오스케줄 버그 수리**
5h 윈도우 resets_at을 캐시에 저장. 기존 오프셋 계산 버그(윈도우 경계 오스케줄)
동시 수리.

### DGN-829 -- 인지 출력 포맷

**telegram.md bold 규칙 정정**
브릿지 레이어가 이미 <b> HTML 렌더를 처리하므로 telegram.md의 마크다운 bold(**)
추가 지시 제거. 이중 적용 방지.

**이모지 섹션헤더 채택 + SECTION_GLYPHS 팔레트**
✅📌📋 글리프를 SECTION_GLYPHS 팔레트로 정의. "복잡·긴 내용에서만" 적용 게이트 --
단순 답 = 평문 유지. config/agent.conf에 SECTION_GLYPHS env 추가.

**AGENT.md L0 응답골격 게이트 명문화**
L0 골격: 단순 답 = 결론 1칸 / 결정 有 = 결론+근거+결정 3칸 고정 배치.
기존 5원칙 + 출력형식 5매핑 위 레이어(대체 아님). 명문 contract로 고정.

**self-update 통지 라벨 글리프화**
self-update 완료 노티스에 SECTION_GLYPHS 적용. 업데이트 노티스 시인성 개선.

### DGN-840 -- 통지 테스트 평문화 위생
