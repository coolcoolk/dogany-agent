## Highlights

### 1. 공개본이 사본이 아니라 산출물이 됐다 (DGN-1276 M3)

지금까지 공개 브릿지 레포는 **손으로 유지하는 사본**이었다. 정본에서 무엇을
빼고 무엇을 넣을지가 사람의 기억에 있었고, 그래서 공개본에만 있는 수정이
쌓였고(v2.1.0 이 역류 상환 8건으로 되가져온 그 부채), 반대로 빠져야 할 것이
나갔다.

이 판에서 그 관계가 뒤집혔다. **생성기가 트리를 만들고, 리포터가 격차를 재고,
발행기가 게이트를 걸고 얹는다.**

- `scripts/publish-bridge.sh` 신설. **기본이 dry-run**이고 `--force` 가 없다.
  `--execute` 도 OSS 클론에 로컬 커밋 하나만 만든다 -- push / tag / remote
  접촉 0.
- 발행 전 게이트 7종, 전부 hard blocker: **S** estate 산문(전용 빈 baseline,
  아무것도 grandfather 하지 않는다) / **T** 내부 티켓 ID / **R**
  staged reference / **C** 소비자 스위트 / **L** 착지 델타 + 역류 ratchet /
  **V** 버전 3점 정합 / **W** secret-sweep(조립본 전체).
- 모든 게이트는 **첫 실패 후에도 끝까지 돈다.** 부분 리포트는 발행-수정-재발행을
  강요하고, 재발행은 매번 공개 이벤트이기 때문이다.
- `--ack-landing`: "예상 델타"의 정본이 없다(매니페스트 제외 집합 21 vs 실델타
  70+35). 없는 기준을 발명하는 대신 조작자가 읽은 수를 진술하고 기계가 대조한다.
  dry-run 이 그 수를 출력하므로 복사 1회 비용이지만, **읽기 전에는 줄 수 없다.**

안전 계약 셀프테스트 44케이스(이후 45)를 함께 세웠다. 공개 레포는 append-only 라
"발행하면 안 될 것을 발행했다"에 undo 가 없어서, 이 테스트가 지키는 것은 전부
**거부(refusal)** 쪽이다: `--force` 부재 / push·tag 미호출 / 브랜치 생성이 verdict
뒤에 온다(줄번호 대조) / 게이트가 권고가 아니라 record 된다.

**발행 자체는 하지 않았다.** 발행기와 게이트가 이 판의 착지분 전부다.

### 2. 막힌 순서가 곧 부채 목록이었다 (DGN-1289 -> DGN-1292 -> DGN-1305)

발행 전 게이트를 순서대로 켜자, 한 게이트가 열릴 때마다 **그 뒤에서 한 번도
돌아본 적 없는 게이트**가 드러났다. 이 판의 상환은 그 순서를 그대로 따라간다.

- **gate E4 (staged reference) 10건 -> 0.** export 트리 안 참조가 export 트리
  밖 파일을 가리키던 항목. **예외 등록 0건** -- 전부 문장 수정으로 해소했고
  게이트를 끄지 않았다. 8건이 브릿지 원장(`UPSTREAM.md`)이 미출하 개발 기계를
  이름으로 부르던 것이었다.
- E4 가 열리자 그 뒤 **gate S(estate-scrub)가 처음 실행됐고 47건이 적재됐다.**
  E4 가 계속 선행 차단하던 탓에 한 번도 안 돌던 게이트다. 개발 이력(원장 108개
  항목)을 정본 전용 로그로 분리하고 코드 주석의 인스턴스 고유명을 역할명으로
  개서해 47건 해소.
- 남은 어휘 39건 -> 18 -> 0. 주석·독스트링·테스트 픽스처만 손댔고 **로직 변경
  0행**(코드행 대조 확인). 사용자 대면 문구 1건은 오너 게이트로 escalate 해서
  형님 승인 후에 교체했다(아래 10절).
- 원장 자체와 킷 계약 픽스처는 **개서가 아니라 제외**로 갔다. 개서하면 실측
  계약을 날조 계약으로 바꾸게 되기 때문이다(형님 결정, C3(2) b안). 비글롭
  단일 경로 소유 + most-specific-owner-wins 라 과다제외가 구조적으로 불가능한
  형태로 배선했다.

실측(v2.1.0 태그 트리 + 이 기계): E4 violations 10 -> 0, export 427 -> 425 ->
424, priv-blocked 9 -> 11 -> 12, E2/E2b/E3/secret-sweep 무변동 green.

### 3. 사내 티켓 ID 가 외부 사용자의 시스템 프롬프트로 나가고 있었다

게이트 T 를 i18n 카탈로그로만 잡으면, **실측된 유출이 사는 파일이 무방비**다.
현 공개본이 프롬프트 조각을 카탈로그가 아니라 `messages.py` 리터럴로 들고 있다:

    messages.py:177  "## Subagent Task Delegation (DGN-086)"      (상시 주입)
    messages.py:197  "## Progress Narration vs Final Answer (DGN-699)"  (fold 모드)

양성 대조로 검증했다 -- 같은 게이트, 두 트리:

    현 공개본 트리   T1 = 2 (위 두 줄을 정확히 지목)  -> BLOCK
    생성 트리        T1 = 0                          -> 통과

정본은 이 카피가 i18n 카탈로그에 있고 `messages.py` 는 `t()` 호출만 하므로 오늘은
어느 범위든 초록이다. 확장의 값은 **회귀 경로를 막는 것**: 카피가 `messages.py`
로 되돌아가면 게이트가 다시 잡는다.

카탈로그 2키는 개서가 아니라 리전 분기로 처리했다 -- 정본(오너 빌드) 문구는
바이트 무변경이고 공개 빌드만 티켓 ID 를 뺀 문장을 싣는다. user-facing 카피를
임의로 바꾸지 않기 위한 선택이다.

### 4. 역류를 재는 기계와, 늘면 막는 래칫 (DGN-1313, 게이트 5d)

형님 결정(2026-09-07) "리포터부터". 발행 배선은 하지 않고 **델타를 재는 기계**만
세우고, 정본 stable 컷에서 역류가 늘면 릴리스를 막는다.

기존 드리프트 도구를 확장하지 않고 신규로 간 근거 4건을 스크립트 헤더에 박았다:
짝이 다르다(RAW 정본 vs OSS 워킹카피 / 생성 트리 vs OSS git ref) · 이름이
반대다(FORWARD/REVERSE 정의가 정반대) · 범위가 다르다(테스트 제외라 역류 항목
일부를 아예 못 잰다) · 지위가 다르다(그쪽은 "a REPORTER, never a gate").

- **REVERSE 를 diff 줄이 아니라 심볼로 센다.** `X = 1` -> `X = 2` 같은 정본측
  수정이 줄 축에서는 "OSS 전용 줄"로 잡혀 래칫을 매주 밀어올리고, 그러면 피하려
  했던 릴리스 동결이 뒷문으로 되돌아온다. 줄 축 수치는 참고용으로만 찍는다.
- **래칫은 발명하지 않고 기존 estate-scrub 형식을 그대로 이식**했다. baseline
  부재 = 아무것도 면제 아님.
- 게이트 5d: REVERSE 초과 -> die(**성장에는 우회 플래그가 없다**) / FORWARD > 0
  -> "OSS 발행 대기 N건" 통지, 막지 않음 / 측정 불가 -> die unless
  `--confirm-bridge-delta`. 기존 5c 는 손대지 않았다(핀 커밋 축은 이 게이트가
  볼 수 없는 축이다).

첫 실수치(2026-09-07): FORWARD 103(신규 69 + 상이 34, 정본 전용 15,512줄),
REVERSE 98 hit / 13파일, CRUFT 3. 이전 사이클의 손 감사 결과를 **사람이 아니라
기계가** 재확인했다.

### 5. 릴리스 스위트 자신이 빨간 채였다 (DGN-1315)

릴리스 게이트를 지키는 테스트가 정작 자기 픽스처를 못 갖춰 **모든 stable-lane
호출이 게이트 5bb/5bd 에서 즉사**하고 있었다. 픽스처가 `releases/vX.md` 와
copy-approval 레코드를 안 만들었기 때문이다. 이미 초록이던 대조군 스위트의
픽스처 패턴을 그대로 이식했다.

    test-release-hardening.sh        PASS=21 FAIL=14 -> 35 / 0
    test-release-devcut.sh           PASS=47 FAIL=3  -> 54 / 0
    test-release-public-coupling.sh  PASS=4  FAIL=20 -> 24 / 0

`release.sh` 는 한 줄도 건드리지 않았다(diff 0줄 확인). 곁다리로 잡힌 것 하나:
devcut 의 "정확히 5개"라는 단언은 픽스처 문제가 아니라 **낡은 단언**이었다 --
그 사이 dev 면제 게이트가 정당하게 9개로 늘었다. 매직넘버를 이름 목록 대조로
교체했다. 숫자만 올리면 다음 추가 때 재발한다.

### 6. 앵커 판정이 두 축 모두 틀려 있었다 (DGN-1293 / DGN-1294)

- **술어 축**: 앵커 여부를 **파일명에 "anchor" 가 들어있는지**로 판정하고
  있었다. 파일명에 그 단어가 없는 실제 앵커가 통째로 누락되는 false green.
  frontmatter `class:anchor` 로 이관했다.
- **활성 축**: 활성 판정이 이미 폐기 선언된 손유지 필드를 읽고 있었다. 어떤
  티켓도 그 값을 유지하지 않으니 활성 앵커가 **항상 0**이었고, 0은 조용한
  성공(drift=0)으로 출력됐다. 유지되는 축(`status:`)으로 옮기고, 앵커 0건은
  정합이 아니라 **스캔이 아무것도 보지 못했다는 신호**로 SCAN-FAIL 처리한다.

실측: anchors_active 0 -> 4, 그동안 가려져 있던 실드리프트 13건이 가시화됐다.
회귀 케이스를 양쪽 축 모두에 추가했다.

### 7. 이력을 뺐더니 기계 독자가 끊겼다 (DGN-1292 -> DGN-1297)

2절의 개발 이력 분리는 옳았지만, 그 파일에서 한 줄을 지우면서 **그 줄을 읽던
기계**를 같이 끊었다. 락스텝 테스트가 빨개졌다.

처방은 되돌리기가 아니다: **현재 rev 앵커 1줄만 원장에 남기고, 106항목 이력은
정본 전용 로그에 존치**한다. 이력을 로그로 옮기는 안은 실측으로 기각했다 --
그 디렉터리는 인스턴스 배송 채널 어디에도 없어서(라이브 인스턴스 2곳 모두 해당
파일 부재) 독자를 그리로 옮기면 **상시 skip = 독자 0**, 즉 이 판이 고치려는
바로 그 병의 재발이 된다.

같은 조사로 전수 재조사를 돌려 **끊긴 독자 1건을 추가 발견**했다. 그 스위트는
다른 사유로 이미 격리(KNOWN-RED)돼 있어서, 새로 끊긴 축이 격리에 가려 러너에
안 보였다. 격리는 손대지 않고 복구만 했다(PASS 6 -> 7).

    검증 2회 재현:  RESULT: PASS-WITH-GAPS ... failures=0  (rc=0)
    직전 기준선(동일 명령):  RESULT: FAIL ... failures=1

### 8. 한 워크스페이스 전용이던 감시 도구를 함대 형상으로 (DGN-1331)

7개 파일이 한 인스턴스에만 있었다. 템플릿으로 이식하면서 **하드코딩된 자기
이름**을 전부 걷어냈다 -- 이식이 아니라 형상 변경이었고, 근거는 전부 실측이다.

- 귀속 게이트의 READING 술어가 특정 슬러그 하드코딩이라 **다른 에이전트가 쓴
  문서는 이음매를 표시할 방법 자체가 없었다** -> `<agent>-reading:` 로 일반화.
- claim-source 테이블의 INTENT_REQUIRED 가 한 원장 접두사 리터럴이라 다른
  접두사를 인용하면 차단됐다 -> 티켓 id 모양으로 일반화.
- parity 검사기가 형제 경로를 하드코딩하고, **없으면 실측한 적 없는 divergence
  를 보고**했다 -> local/peer + 형제 스캔, peer 없음 = SCAN-FAIL(exit 2).
- baseline 린트의 면제 목록이 한 페르소나 문구만 담고 있어서 나머지 페르소나
  4개의 정당한 데이터값 전부를 위반으로 보고했다(2026-09-08 실측) -> 양쪽 등재.
- ATTRIBUTOR 컬럼을 일반 티켓 모양으로 넓히려다 `utf-8` / `sha-256` /
  `ISO-8601` 오탐이 **측정돼서** 원래의 명시 목록을 유지했다(회귀 테스트 첨부).

테스트 21/21 + 21/21, 캐노니컬 위치에서 통과.

### 9. 산출물 판정이 바이트를 보고 있었다 (DGN-1337)

디스패치 종료 통지가 "산출물이 남아 있다, 회수가 먼저다"를 **산출 0인 취소
런에도** 지시했다. 세션 초기화만으로 로그가 1-13KB 나오는데 판정이 바이트수만
봤기 때문이다. 표본 3건(13083B / 1016B / 878B) 전부 도구 호출 0, 3회 전부 오탐.

**모순은 통지문 안에 이미 있었다**: 커밋 수 0을 함께 출력하면서 판정은 바이트만
봤다. 이제 세 신호(커밋 / 도구 호출 / 발화)를 전부 노출하고 판정도 그 셋을 본다.

함대 전체가 같은 파일을 들고 있어 매 디스패치마다 자동 재발하던 부류다.

### 10. 형님 눈에 보이는 변화는 둘뿐이다

이 판의 착지분은 대부분 발행 기계다. 실제로 화면이 달라지는 것은 둘이다.

- **헤딩 레벨 글리프 단조 세트 교체** (형님 확정 2026-09-07). 기존 세트는
  H1(작은 사각형)이 H2(큰 마름모)보다 작아 **깊이가 모양에서 안 읽혔고**,
  실사용 최빈값인 H3(최근 12세션 100회)가 가장 약한 기호였다. 같은 사각형
  계열에서 크기만 내려가는 세트로 교체. 되추론 코드 없음(순방향 인덱스 조회
  1곳뿐, grep 0건), 옛 글리프 잔여 0건, 테스트 30 passed.
- **업데이트 실패 통지에서 담당자 이름 제거** (형님 승인 2026-09-06). 공개본을
  받은 사용자에게 이 estate 의 에이전트 이름이 뜨던 문구다. **받는 사람은 그
  이름이 누군지 모른다.** 사실 내용 불변, 화자만 일반화. 원래 dec-094 로
  승인됐던 문구라 형님 재승인을 받고 교체했다.

### 11. 상환 머지 -- 24훅을 훅 단위로 판정했다

개발선과 릴리스선이 갈라진 뒤 처음 온 큰 상환 머지다. 12파일 24훅 전부를 훅
단위로 판정했고, **`-X ours` / `-X theirs` 일괄 적용을 금지**했다. 해소 원칙은
근거 순으로 고정했다: (1) 사실 보존(복수/소유격/"live" 같은 원문이 담던 사실을
잃지 않는 쪽) (2) 이미 발행된 어휘와의 일치 (3) 순수 동률이면 이번 판 스코프의
본류 (4) **형님 승인본·오너 게이트는 무조건 고정**.

자동머지가 조용히 삼킬 뻔한 손실 1건을 되돌렸다: 한쪽이 픽스처 슬러그를
일반화했는데, 다른 쪽 결정이 바로 그 안을 "실측 계약을 날조 계약으로 바꾼다"는
이유로 기각하고 제외로 갔다. 머지 트리에서는 제외가 서므로 개서 사유가
소멸한다 -> 실측본 복원.

### 12. 그 외 착지분

- **fable 소진 마커 writer 를 템플릿으로 전파** (DGN-1158 / DGN-1301). 모델
  강등 게이트가 템플릿에서 태어난 신규 인스턴스에는 **영구 no-op** 이었다.
  writer 2경로(detached worker 종료 / 메인세션 훅)를 모두 출하분에 싣고,
  4자(2 writer / 2 reader) 경로·필드·만료원 합의를 확인했다. 이식 시 경로 앵커
  하나를 템플릿 계약에 맞게 바꾼 것이 유일한 변경이다.
- **spawn 게이트 판정을 기록으로 남긴다** (DGN-1230). 게이트가 실제로 돌았는지
  워커·사후감사가 추측하지 않도록 fresh/stale 판정을 기계 자신의 기록으로
  남긴다. 라이브 착지분의 정본 환류이고, 환류 후 경로토큰 정규화 기준
  byte-identical(잔여 drift 0).
- **카탈로그 id 개명** (health-trainer -> `pack_health`, `kind: pack` 추가).
  카탈로그 id 는 EXACT match 조인 키라 매니페스트와 갈리면 설치가 거부된다.
  한쪽이 먼저 옮겨져 양쪽 다 빨간 중간상태였고, 판정 술어가 '대응 여부'라
  **순서로는 피할 수 없어** 창을 짧게 하는 것이 유일한 방어였다. 적용 전
  2 failed -> 적용 후 11 passed / 0 failed. `kind` 명시는 침묵 기본값을 선언된
  사실로 바꾼 것이다.
- **v2.2 태그 선행조건 2건**: 발행기 테스트에 test-lane 선언 추가(측정 1.0s),
  설치 메뉴 테스트의 기대 id 를 카탈로그 개명에 맞춤.
- **secret-sweep cat5**: 리포트에서 머신 절대경로를 인스턴스 루트 상대표기로
  교체.

## 알려진 잔여

1. **공개 제품 미러 발행이 이번에도 안 됐다.** 막는 게이트가 바뀌었다. E4 는
   해소됐고(실측 PASS), 이번엔 그 뒤 estate-scrub(S)가 **33건**으로 막는다.
   원인은 전부 이 판에 실린 감시도구 파일들의 주석·독스트링·테스트 리터럴에
   남은 인스턴스 고유명이다(8절의 이식분 5파일). 정본(main) 태그·머지는 무영향
   -- publish 는 canonical 쓰기와 분리된 단계로 커플링되고, 이 실패로 canonical
   이 되돌려지지 않는다. **미착지.**
   실측 2026-09-08 `scripts/publish.sh --dry-run`:
   `gate E PASS export=435 / E2 violations=0 / E2b / E3 / E4 violations=0 /
   secret-sweep CLEAN / gate S BLOCK 33 unbaselined`.
2. **OSS 브릿지 공개 레포도 아직 발행 안 됐다.** 발행기와 게이트 7종은
   착지했지만 `--execute` 는 돌리지 않았다. 역류(REVERSE 98 hit / 13파일)는
   해소가 아니라 baseline 으로 **동결**된 상태이고, 래칫은 그 위로 자라는 것만
   막는다. 상환 자체는 별건. **미착지.**
3. **`v2.1.0` stable 태그가 어디에도 없다.** 그 판은 정식 발행 없이 회수됐고,
   장부(instances.md)의 canonical-published 주석은 커밋 sha 를 "tag" 로 적고
   있다. 결과: 공개 미러가 실제로 돌면 미러-포워드가 **v2.0.3 -> v2.2.0** 으로
   한 칸 건너뛴다. 미러는 정본 stable 태그를 오름차순으로 훑는 구조라 존재하지
   않는 태그는 애초에 후보가 아니다 -- 브릭은 안 나지만 v2.1.0 은 공개본 계보에서
   **영구 결번**이 된다. 장부 표기 정정은 이 릴리스의 3곳 편집 범위 밖이라
   기록만 남긴다.
4. **user-summary 문구가 형님 미승인이다.** `copy_approved` 레코드가 없으므로
   릴리스 게이트 5bd 는 BLOCK 이고, **그것이 의도된 상태다.** 이 블록은 형님이
   실제로 읽는 면이라 초안을 최종으로 취급하지 않는다.
5. **staging 링이 이번에도 사실상 없다.** dev 카나리는 `v2.2.0-dev.1` 하나뿐이고,
   dev 채널을 소비하는 인스턴스는 2대(그중 1대는 이 판을 만든 워크스테이션
   자신)다. `promote.sh --check` 실행 기록도 이 범위에 없다. 링 자체의 실가동은
   여전히 별건.
6. **릴리스 전 리포트 3종이 없다.** 이 판에 대한 release-preflight / doctrine-review
   / adversarial-grill 리포트가 모두 부재하다(최신 preflight 는 2026-08-24,
   최신 grill 은 2026-08-27). backlog near-term 에 2026-08-21 자로 이미
   "3연속 무보고" 로 플래그된 항목이 그대로 반복됐다. 형님 판단 대기.
7. **DGN-1272 미착지**: 테스트가 공유 템플릿 트리에 쓰고 치우지 않는다.
   DGN-1269 의 근본이고, 격리 워크트리와 본체의 판정이 갈리는 원인이다.
8. **known-red 격리 14건 유지.** 러너 fast 레인 실측(2026-09-08, HEAD ab043bca):
   `RESULT: PASS-WITH-GAPS -- lane=fast suites=102/153 deferred-slow=46 manual=5
   unlaned=0 known-red=14 stale-quarantine=0 failures=0 degraded=0`, rc=0.

9. **래칫에 stale 항목 23건.** estate-scrub baseline 에 라이브 히트 0인 등재가
   23건 쌓였다(게이트 설계상 비차단, "drop when convenient"). 추가로 tighten
   가능한 항목 3건이 함께 보고된다.
10. **CHANGELOG 2.2.0 의 한 항목이 이 판의 변경집합에 없다.** CHANGELOG 는
    "선언-미이행 게이트가 두 형상을 더 막는다 -- 티켓 선언과 머지 선언"을

    템플릿에는 없다.** 실측 2026-09-08: 범위 내 `output_gate.py` 변경 커밋

11. **`config/v2.conf` 축은 이 판과 무관하다.** v2-flag-track 대상 모듈이 이
    변경집합에 없어 live-only-assets 각주 대상이 없다(실측: 범위 내 해당 파일
    무접촉). 해당 자산은 VERSION/CHANGELOG 범위 밖이라는 사실만 유지된다.
