en: |
  This release touches dispatch notices, the work board, notice wording, side-question (/btw) answers, and skill authoring.
en_detail: |
  · Dispatch notices: a notice now arrives when background work starts, not
    only when it finishes; several dispatches started together arrive as one
    message.
  · Job names: on an instance that does not run in English, the work board and
    dispatch notices show a human-readable job name instead of the internal
    hyphenated label.
  · Notice content: a notice can no longer carry a run number, a commit hash,
    an absolute path, or an exit code. A message containing one is refused
    outright instead of being sent with the value quietly removed.
  · Notice wording: the completed and failed outcomes of a dispatched run each
    read as one settled sentence. A notice about a state the agent cannot
    recover from now lists the recovery steps that work without the agent,
    simplest first. The backup and weekly notices were reworded in the same
    pass.
  · Work board: a run stopped on purpose used to sit there presumed dead. A
    stop is now recorded as it happens and the run leaves the live list at
    once, while a run that goes silent with no stop record raises the same
    alarm it always did.
  · Side-question (/btw) answers: when a side question coincided with a
    background task notification, only a failure line came back and the real answer was
    discarded. The answer now arrives in that case too.
  · New skills: writing a skill definition file now requires answering where
    the skill lands and which agents it is active for. Skills already
    installed are untouched.
