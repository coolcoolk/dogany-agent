# v1.25.0 -- Self-update landing hardening

Date: 2026-08-03

## Purpose

Make self-update landing correct across instance shapes. Framework code fixes
should reach every instance regardless of how its local schema or agent
definitions have diverged, and the pre-push secret gate should survive
workspace relocation.

## Changes

### DGN-656 -- update.sh --code-only landing path
Divergent-lineage instances (framework migrations plus a domain pack, without a
later framework migration) had no way to accept a framework code fix without the
updater also forcing the pending DB migration. `--code-only` (alias
`--no-migrate`) now lands framework code and files while leaving the schema
frozen: pending migrations are enumerated and skipped, `user_version` is
untouched. A forward-pin guard holds back any code file whose expected schema
version outruns the frozen database (rather than landing a verb that would
crash), and the flag propagates through the release-channel re-invoke.

### DGN-663 -- .claude/agents/ synced as a framework service
Framework agent definitions were copied only at mint time and never delivered to
existing instances by update; the preserve-checker also false-warned on those
`.dogany-preserve` entries. `.claude/agents/` is now in the framework services
manifest, so agent-definition improvements reach live instances. The
per-instance preserve list still protects locally-customized definitions (no
`--delete`, exclude-anchored), verified against the preserve contract.

### DGN-668 -- canonical pre-push secret gate
The pre-push hook was a per-clone untracked file and went inert after the
workspace relocation (`core.hooksPath` pointed at `git-hooks/`, which had no
pre-push). A canonical `git-hooks/pre-push` (full secret sweep categories plus
the D7 outbound-diff gate) is now tracked, seeded into the mint template, and
installed by mint.sh, with `secret-sweep.sh` genericized to instance-relative
paths.
