## 목적 (purpose)

앵커: **팩 게이트의 단일-킷 가정 제거** -- lint 게이트(compat-lint)와 설치기(pack_install)
양쪽에 lifekit이 하드코딩 상수로 박혀 있어, 두 번째 킷은 구조적으로 검사를 통과할 수도
설치될 수도 없었다.

문제: 게이트 전반부(compat-lint)와 후반부(pack_install)가 킷 이름을 매니페스트에서 읽지
않고 리터럴로 들고 있었고(DGN-1002/1003), 게다가 손상된 JSON 매니페스트는 "아무것도 관측
못함"과 "구형 팩임을 관측함"이 같은 legacy-grace 경로로 합류해 검사 0건 초록불로 통과했다
(DGN-1004). 킷 스킬의 크루 공유 계층(sharing_mode)도 부재해 인스턴스마다 사본이 분기했다
(DGN-956). v1.40.0은 이 네 장을 한 앵커(멀티-킷 준비)로 묶어 닫고, 안전 가드 2건
(DGN-1005 캐노니컬 트렁크 가드, DGN-1008 지식창고 유실 봉쇄)과 오너 커맨드 1건(DGN-997
`/restart`)을 라이더로 접어 낸다.

Anchor: DGN-1002 + DGN-1003 (refs DGN-1004, DGN-956; riders DGN-997, DGN-1005, DGN-1008)

## Highlights

1. **킷명 일반화 -- 게이트 전반부 (DGN-1002).** compat-lint의 KIT_NAME이 매니페스트
   `provides_kit`에서 유도된다. 키 부재 = lifekit 레거시 기본(기존 팩 무변), 존재 시
   `^[a-z][a-z0-9_-]{0,31}$` + 프레임워크 예약어 blacklist fail-closed(오염된 이름이
   경로 allowlist를 구동하지 못하도록 즉시 ABORT). `capabilities.db_lane=false` 선언으로
   C3/C6 역량 SKIP -- 단 false 선언 + `database/` 파일 적재는 밀수로 간주해 FAIL.

2. **킷명 일반화 -- 게이트 후반부 (DGN-1003).** pack_install의 db-init / migrate /
   service_facade / SHARED_ROOT / config merge 등 lifekit 리터럴 전지점 일반화.
   이름 계약은 compat-lint와 **의도적 복제**(설치기는 게이트 부재 시 SKIP 경로가 실존해
   게이트 신뢰 금지) + TL 락스텝 매트릭스 28케이스로 드리프트 알람 고정.

3. **손상 매니페스트 fail-closed (DGN-1004).** JSON 파싱 실패 -> legacy-grace -> exit 0
   ALL PASS 구멍 봉쇄. legacy-grace 앞에 매니페스트 파스 게이트 신설: 파싱 실패 /
   top-level 비-object는 FAIL + ABORT. 진짜 구형 팩은 그대로 통과(테스트 고정).

4. **kit skill `sharing_mode` primitive (DGN-956).** 매니페스트 skills[] 블록으로 스킬을
   share(크루 공유 canonical + 인스턴스 symlink) / own(사본, 기본값) 분류. 링크 자리의
   diverged 실디렉토리는 fail-closed. update.sh R9 가드: 프레임워크 업데이트가 share
   링크를 관통해 인스턴스 placeholder 값을 공유 본체에 각인하는 것을 차단. compat-lint
   C7 신설(모드 어휘 / 사어 선언 / 템플릿 이름 충돌 거부). contract_version=1 유지
   (additive).

5. **`/restart` 오너 커맨드 (DGN-997, 라이더).** 재시작의 범용 슬래시 진입점 신설
   (기존엔 `/authsync` 성공 응답 안의 버튼뿐). 기존 오너 게이트 재사용,
   `self_restart.sh --trigger user` 즉발, dec-094 즉시 ack("재시작합니다. 곧
   돌아옵니다.") 후 완료 push 별도. DGN-994 CTA 버튼과 래치 공유 -- 교차 이중발사 차단.
   라이브 Metal 검증분의 캐노니컬 back-land.

6. **캐노니컬 트렁크 가드 (DGN-1005, 라이더).** pre-commit이 main 위 plain 손편집
   커밋을 차단. 머지 커밋 / 비-main 브랜치 / VERSION+CHANGELOG 릴리스 커밋은 통과,
   `--no-verify` 우회 명시. 레포 루트 추적파일 `.dogany-canonical` 마커에만 무장 --
   마커는 update.sh 섹션 rsync 대상이 아니고 .template에도 없어 라이브/민팅
   인스턴스에서 구조적으로 inert(fail safe-off).

7. **knowledge-snapshot destination-ahead 가드 (DGN-1008, 라이더, 긴급).** 파괴적 미러
   (rsync --delete)가 de-facto 캐노니컬이 된 라이브 지식창고(실측: 라이브 v7/34건 vs
   퍼블리셔 v3/24건)를 지울 수 있던 역방향 상태 봉쇄. 목적지가 소스보다 앞서면 동기화
   전체 거부, 버전 파싱 불가도 fail-closed. 부수: STEP 6 종료코드 삼킴(PIPESTATUS) 수정.

## 인수된 한계

- pack_install 잔존 lifekit 리터럴 4곳은 킷 분기 바깥(agent/module 팩 경로) --
  kit-class 스코프 밖, 의도적 무접촉 (DGN-1003).
- main에서 메시지만 바꾸는 `--amend`는 가드에 차단됨(스테이지 diff가 비어 릴리스 커밋
  감지 불가) -- `--no-verify`가 의도된 경로. `merge --squash` 착지도 차단(정규 흐름은
  `--no-ff`이므로 수용) (DGN-1005).
- knowledge-snapshot의 publish/redeliver 반쪽은 여전히 미설계(DGN-402는 읽기 반쪽만
  규정) -- 가드는 유실을 불가능하게 만들 뿐, 정방향 퍼블리시 규율은 후속 (DGN-1008).
- `/restart`는 `--resume-intent` 미배선: 브릿지는 세션 in-flight 상태를 모른다
  (= self_restart.sh 계약상 "no in-flight" 선언, DGN-706) (DGN-997).
