## Fixed

### DGN-452: push.sh CLAUDECODE guard + stdin/timeout/set -e hardening (4-way)

`agents/.template/routines/push.sh`: four reliability hardening items propagated
from Metal canonical (Metal commit c1d41eb):

1. CLAUDECODE guard (B): when `CLAUDECODE=1` is set (inherited from an active
   Claude Code session), any invocation with `--prompt` exits immediately with a
   descriptive error and a `--text` hint. Prevents the silent nested-session
   rejection where `claude -p` exits non-zero with no useful message.

2. Per-call timeout (A / M4): `timeout 60` (Linux) or `gtimeout 60` (macOS
   Homebrew) is resolved once per invocation and prefixed to the `claude -p` call.
   Caps wall time to 60 seconds per retry attempt, preventing orphaned stdout holds
   from blocking the caller indefinitely. Falls back to no timeout when neither
   command is present.

3. stdin redirect (A / M2): `< /dev/null` added to the `claude -p` call.
   Prevents the subprocess from inheriting the caller's stdin and hanging when
   stdin is a terminal or a blocking pipe.

4. `set -e` safety (A): `|| true` appended to the claude call inside the retry
   loop. The outer script runs under `set -e`; without this, a non-zero exit from
   `claude -p` would abort the entire script on the first attempt rather than
   allowing the retry logic to continue. The `BODY` emptiness check already gates
   the retry condition correctly.

Propagation: 4-way (Metal canonical already carried the fix; template, and
downstream estate instances via `update.sh` are the propagation targets).
