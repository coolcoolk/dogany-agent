# Release notes -- v1.18.1 (2026-07-31)

Type: PATCH/HOTFIX (mirror adapter forward-tolerance; no schema change; no
migration required for consumers of this release).

## Summary

Hotfix on v1.18.0. One commit since the prior release tag.

The calendar mirror adapter carried an exact-match version whitelist `{11}` that
gated polling against the live database user_version. Live Ag/Warg event schema
reached v15 via a sequence of domain relationship-module migrations
(013_persons_relations, 014_relation_type_unify, and earlier Ag-local migrations),
none of which are present in the canonical framework. The adapter rejected v15 with
`MigrationRequired: event schema user_version=15, expected one of {11}`, crashing
every 5-minute mirror poll and taking two-way calendar sync down for approximately
two days. Ag outbox accumulated 13 stuck entries; owner-delete (dec-011) was
blocked in the poll queue.

DGN-654 replaces the hard whitelist with a MIN_USER_VERSION=11 floor plus a
capability probe. The probe checks every table and column the adapter actually reads
via PRAGMA introspection; a live database at any version at or above the floor is
accepted as long as every required capability is present. `update.sh` reverse-drift
guard updated to parse the scalar minimum. REQUIRED_CAPABILITIES covers all
mirror-relevant surfaces including the dec-011 settle path (derived_from et al.)
that caused the silent re-crash risk identified during adversarial grill.

Release approved by owner: explicit dispatcher authorization (2026-07-31,
DGN-654 worklog entry "릴리스 (2026-07-31)").

## Fixed

### DGN-654: mirror adapter version gate -- MIN floor + capability probe

`mirror/sdk_bridge.py`:

- Replaces `ALLOWED_USER_VERSIONS = (11,)` with `MIN_USER_VERSION = 11` floor.
- Adds REQUIRED_CAPABILITIES dict: adapter introspects the tables and columns it
  actually reads via `PRAGMA table_info`. A database at any user_version >= 11 is
  accepted if every required capability is present; version alone is no longer the
  acceptance predicate.
- REQUIRED_CAPABILITIES includes all event-table columns (including updated_at,
  created_at, owning_agent, time_mode, rec_exception, derived_from, derived_role,
  derived_pinned) and the roller_log table. The derived_from column covers the
  dec-011 owner-delete settle path; its omission would have caused a re-crash on
  landing at the first mirror poll that processed a deletion.
- `update.sh` reverse-drift guard updated to parse the scalar MIN_USER_VERSION
  value instead of the old tuple literal.

Grill history (commit e9578ef, grill-fix before 2c84488): adversarial grill
(Fable, independent capability re-extraction) identified 9 missing capabilities
in the initial probe -- 8 event table columns + roller_log. All 9 are present from
user_version 11 (additive, no version-gating needed). False-SHIP was blocked.

Mirror test suite: 57/57 pass (commit 2c84488).
