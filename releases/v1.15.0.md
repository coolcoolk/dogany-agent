## Changed

### dec-090 / DGN-446: RULES.md work-items line -- positive ticket-surface
ownership phrasing

`rules/RULES.md` (and `.template/RULES.md` via symlink): the work-items
memory routing rule is rephrased from a negative command ("work items are
never memory") to a positive system-of-record statement: work-items live on
the ticket surface (status/priority/lifecycle); memory holds durable facts
only.

Rationale: negative-command framing in RULES.md has been found to produce
fragile rule-following (rule unfollowed -> design a forcing point). Positive
ownership phrasing is more durable and aligns with dec-094 (forcing-point
principle). No behavior change for instances already following the rule.

---

### DGN-553: mirror ALLOWED_USER_VERSIONS tightened to (9,)

`mirror/sdk_bridge.py`: the `ALLOWED_USER_VERSIONS` rollout gate narrows
from `(8, 9)` to `(9,)`. The 24-hour M1 window held since schema-009 landed
live on 2026-07-24 22:18; no v<9 nodes remain. Tightening at M2 closes the
backward-compat window and enforces the settled schema pin.

---

### DGN-536: status-footer Rev 11 -- [콘솔액션] dashboard section

to Metal canonical). Changes in Rev 11:

  console decision-actions from `decision-actions.md`.
- Section is journal-gated: absent `decision-actions.md` -> section omitted;
  no output change for instances that do not use the dashboard action surface.

`agents/.template/routines/tests/test-status-footer.sh` (159 lines, new):
regression suite covering Rev 11 section rendering and the journal-absent
no-op path.

`opus,sonnet,haiku`. Sonnet remains the recommended default model; fable
stays max-only. Existing user-customized `BRIDGE_MODELS` values are untouched
by the update backfill.

## Fixed

### DGN-562: brief blank-line fix + session-recap per-half 200 cap

Two template fixes propagated from Metal main:

1. `agents/.template/routines/generic-brief.sh`: `compose_prompt` now inserts
   a blank line between sections (parity with Metal main). Previously sections
   ran together when the brief had multiple content blocks.

2. `agents/.template/routines/session-recap.py`: `_DEFAULT_CHAR_CAP` reduced
   from 500 to 200. The cap is now applied per-half (first N chars + last N
   chars of recap content), not as a total. `agents/.template/config/agent.conf`
   comment updated to document `RECAP_CHAR_CAP` as a per-half value. Reduces
   worst-case session-start injection from ~1,000 to ~400 chars for instances
   on default config.
