## Summary

Hotfix follow-up to v1.22.0 (stability GA). One commit since v1.22.0 tag,
touching RULES.md and CHANGELOG.md only.

The prior output rule (RULES `## Output`, line 31) read "No per-step narration
during tool/skill runs; speak on issue or decision." In practice this produced a
pattern of extended silence followed by a wall of text -- the operator receives
no signal that the agent is progressing through a multi-step task. DGN-690
replaces the rule with an explicit cadence: acknowledge at task start and at each
major phase transition; between those two acknowledgement points no per-step
chatter; speak on issue or decision; report results as crisp bullets.

The companion dev-crew RULES symlink unification (dev-crew/rules/RULES.md now a
symlink to the canonical) is a crew-local structural change and is NOT included
in this release scope. Only the cadence rule text shipped in the canonical
dogany-agent RULES.md is attributed here.

Release authorized by owner: explicit dispatcher directive (2026-08-01, DGN-690
dispatch).

## Feature decisions

### Output cadence rule: acknowledge-at-phase vs silence-until-done

Decision point: should the agent narrate each tool invocation, or remain silent
until final output?

Landed: neither extreme. Acknowledge at task start and at each major phase;
between them no per-step narration. Rationale: complete silence across long tasks
creates an opaque wall-of-text arrival with no progress signal (the "silent-then-
dump" anti-pattern observed live). Per-step narration is the opposite extreme and
creates noise. Phase-boundary acknowledgement is the structural midpoint -- enough
signal to confirm work is progressing, no noise between steps. Owner-confirmed via
DGN-690 dispatch (2026-08-01 17:53, 18:02 re-confirmed).
