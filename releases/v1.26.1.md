## Purpose

A maintenance and discipline bundle centered on the framework update notice:
stop it re-firing on every conversation turn, and stop its expandable fold from
dumping the raw English CHANGELOG with ticket refs. Bundled with estate
display-name discipline, a public-sync cadence gate, and a RULES constitution
cleanup.

## Changes

### DGN-735 -- per-version update-notice guard
The SessionStart "update available" notice keyed its once-per-session guard on
`session_id`. This bridge spawns a fresh CLI subprocess per conversation turn,
so `session_id` regenerated every turn and the guard never held -- the notice
re-fired on every turn. The guard is now keyed on the offered VERSION string
with a 7-day re-nag TTL: the notice shows once per new version, at most weekly.

### DGN-738 -- localized notice fold (drop English CHANGELOG + ticket exposure)
The same notice built its expandable fold from the English CHANGELOG section
(`### Added` headers, `(DGN-NNN)` refs). DGN-699 had moved only the
update-COMPLETION notice onto the release-note user-summary; the
update-AVAILABLE fold still scraped English. It now renders the release note's
localized `user-summary` (ko/en) for the resolved language -- local check reads
`releases/vX.Y.Z.md`, remote check fetches it from the public raw URL -- and
falls back to the CHANGELOG scrape only when no summary block exists. The
summary carries no ticket refs, so DGN exposure disappears with it.

### DGN-729 -- estate display-name discipline
A new `DISPLAY_NAMES` config flag (default on) with a language-neutral RULES.md
Output rule: domain agents surface persona display-names; with the flag off,
Metal/crew keep internal slugs and paths. Default seeded in
`agents/.template/config/agent.conf` with documentation.

### DGN-731 -- public-sync cadence gate
A new `scripts/lib/cadence-gate.sh` library integrated into `publish.sh` as
promotion-coupled forcing points FP2/FP3, blocking an out-of-cadence public
push. Thresholds overridable via env; tests included.

### DGN-733 -- RULES constitution cleanup
Removed the dec-094 provenance tag and the asterisk-bold output ban from
RULES.md. The bridge auto-renders markdown to Telegram HTML, so the ban was
obsolete in the medium-neutral constitution; Telegram-specific concerns belong
in the bridge layer. The dec-094 forcing-point principle itself is preserved
(tag removed, not the rule).
